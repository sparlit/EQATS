# Integration Blueprint for hyperliquid-trading-bot-rust into eqats\n\n## Overview\nThe Hyperliquid trading bot provides a clean, asynchronous Rust foundation for market data ingestion, indicator‑based signal generation, and risk‑aware order execution. Its modular structure maps well onto the three eqats domains.\n\n## Data Engines\n- **Market Data Ingestion**: Uses `hyperliquid_rust_sdk` to subscribe to Hyperliquid WebSocket feeds and REST endpoints. This can replace or augment eqats’ current data connectors by providing a ready‑made client for perpetual futures data.\n- **Multi‑Market Handling**: `src/bot.rs` orchestrates multiple `Market` instances, each running its own data feed task on a Tokio runtime. eqats can adopt this pattern to run isolated data pipelines per symbol or exchange.\n- **Timeframe & Indicator State**: Indicators are bound to specific `TimeFrame` values (Min1, Day1, etc.) and store rolling state internally. Integrating this into eqats would allow per‑symbol, per‑timeframe indicator caches without rebuilding the logic.\n\n## Signal & Execution Logic\n- **Strategy Framework**: `src/strategy.rs` defines a `CustomStrategy` that takes risk level, style, and stance as enums and combines indicator signals. eqats could expose a similar strategy configuration API, allowing users to pick from preset styles (Scalp/Swing) and adjust risk/stance.\n- **Indicator Library**: The bot implements a set of technical indicators (RSI, StochRSI, EMA cross, ADX, ATR, EMA, SMA) each as a struct with an `update` method. These can be imported as reusable components into eqats’ signal engine.\n- **Signal Combination Logic**: Signals fire only when multiple indicator conditions agree (e.g., oversold RSI + bullish StochRSI crossover). eqats can adopt this “AND‑of‑conditions” model to reduce false positives.\n- **Order Execution**: `src/executor.rs` abstracts order placement via the Hyperliquid API, handling nonce management and signature. eqats could wrap this executor (or a similar adapter) to send orders to any exchange via a unified interface.\n- **Trade Setup**: `src/trade_setup.rs` holds trade metadata (SL, TP, qty, eq). Integrating this structure would standardize trade tickets across eqats.\n\n## Risk Engineering\n- **Margin Allocation**: Each market receives a `MarginAllocation::Alloc(fraction)` value, dictating what portion of account equity may be used. eqats can expose a similar per‑symbol risk budget.\n- **Risk Levels**: The `RiskLevel` enum (Low, Normal, High) scales position size inside the strategy. Mapping this to eqats’ risk‑engine would allow dynamic leverage adjustment based on market volatility or user preference.\n- **Margin Synchronization**: `bot.rs` continuously reconciles allocated margin with actual account margin, preventing over‑exposure. Implementing a similar margin‑monitor loop in eqats would enhance safety.\n- **Pre‑trade Risk Checks**: Before sending an order, the executor validates that the requested size does not exceed the remaining margin allocation. This check can be directly ported to eqats’ risk‑gatekeeper.\n\n## Integration Steps\n1. **Add the Hyperliquid SDK** as a dependency in eqats (if targeting Hyperliquid) or replace it with eqats’ existing exchange abstraction.\n2. **Copy the indicator modules** (`src/signal/`) into eqats’ `indicators` package, preserving their `update` API.\n3. **Adopt the market‑orchestrator pattern** from `bot.rs`: create a `MarketManager` that spawns a Tokio task per symbol, feeding data into the indicator engine.\n4. **Expose a strategy configuration struct** mirroring `CustomStrategy` (risk level, style, stance) and wire it into eqats’ signal combiner.\n5. **Integrate the margin allocation and risk‑level logic** into eqats’ risk‑engine, using the same enums and validation functions.\n6. **Use the executor as a reference** for building eqats’ order‑sender adapter, ensuring nonce handling and signature generation.\n7. **Write unit tests** based on the bot’s `enginetest.rs` to verify indicator configurations and signal generation.\n\nBy leveraging these concrete components, eqats can rapidly extend its capabilities with a battle‑tested, asynchronous Rust trading bot while maintaining a clean separation between data, signal, and risk layers.
