# Integration Blueprint for 10101 Features into eqats

## Overview

The 10101 repository provides a self‑custodial derivative trading stack built in Rust with a Postgres‑backed coordinator, a local Bitcoin regtest node for testing, and cross‑platform mobile clients. Its core pieces can be mapped to the eqats domains as follows.

## Data Engines

- **Regtest Bitcoin Node**: Spins up a local regtest chain that supplies real‑time block and transaction data. eqats can reuse this as a sandbox market‑data feed for strategy development.

- **Postgres + Diesel**: The coordinator uses Diesel ORM to persist orders, trades, and wallet state. eqats can adopt the same schema for its own persistence layer, leveraging Diesel’s migrations and query builder.

- **Docker‑Compose Services**: All components (coordinator, DB, explorer, faucet) are orchestrated via `just all`. eqats can adopt a similar `justfile` to manage local dev stacks, ensuring reproducible environments.

## Signal & Execution Logic

- **Self‑Custodial Wallet & QR Receive**: The receive screen generates a QR code and offers a “Pay with 10101 faucet” button that defaults to 1 BTC on regtest. eqats can expose a similar QR‑based funding flow for testnets, simplifying user onboarding.

- **Coordinator Matching Engine**: Logs (`data/coordinator/regtest.log`) show the coordinator processing orders. eqats can extract the coordinator’s order‑matching logic (likely Rust) and wrap it as a reusable execution service.

- **Mobile Trade UI**: The Flutter‑based iOS/Android apps demonstrate how to place orders from a mobile client. eqats can reuse the UI components or at least the API contract (REST/WebSocket) used by the mobile apps to submit orders.

## Risk Engineering

- **Observability**: The block explorer (`http://localhost:8080/`) and faucet endpoint (`http://localhost:8080/faucet/`) give real‑time visibility into chain state and test‑fund distribution. eqats can expose analogous endpoints for monitoring positions and risk limits.

- **Log‑Based Monitoring**: Tailing `regtest.log` provides insight into coordinator health and order flow. eqats can integrate similar log streaming into its risk‑monitoring pipeline.

- **Environment Reset**: The `just wipe` command clears the dev state, enabling risk‑free strategy testing. eqats can adopt a comparable reset routine for its backtesting and simulation environments.

## Integration Steps

1. **Add Docker & justfile** – Copy the `docker-compose.yml` and `justfile` from 10101 to eqats, adjusting services to eqats‑specific components (e.g., replace the coordinator with eqats’ execution engine).

2. **Adopt Diesel Schema** – Import the Diesel migrations and models used by the coordinator; map them to eqats’ order and position tables.

3. **Expose Regtest Feed** – Run the regtest node as a service and subscribe eqats’ data‑engine to its block‑via‑ZMQ or RPC interface for real‑time market data.

4. **Wallet‑Funding Flow** – Implement a QR‑receive screen that calls a faucet endpoint (internal or testnet) to fund the wallet, mirroring the “Pay with 10101 faucet” button.

5. **Reuse Coordinator Logic** – Extract the order‑matching Rust crate from 10101’s coordinator and link it as a dependency in eqats’ execution service.

6. **Mobile API Contract** – Document the HTTP/WebSocket endpoints used by the 10101 mobile apps; eqats’ mobile clients can target the same endpoints, enabling cross‑platform reuse.

7. **Observability Endpoints** – Deploy a lightweight block‑explorer UI and faucet service (or adapt existing ones) to provide eqats operators with real‑time chain and fund visibility.

8. **Log Streaming** – Configure the coordinator to write structured logs to stdout; eqats can pipe these into its risk‑monitoring stack (e.g., Loki/Prometheus).

9. **Automated Reset** – Add a `just wipe`‑style target that tears down and recreates Docker volumes, ensuring a clean state for each risk‑testing iteration.
