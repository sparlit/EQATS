# Integration Blueprint for mineralres/rust-share into eqats

## Overview
The rust-share repository provides Rust‑based trading tools, including CTP futures and Tora Stock APIs, a utility crate, a web‑scraping spider, and a trading gateway with an HTTP API for order execution and position alignment.

## Data Engines
- **Spider crate** (`crates/spider`): scrapes financial websites; can be adapted to ingest alternative data (news, fundamentals) into eqats’ data lake.
- **CTP Futures & Tora Stock crates**: provide real‑time market data feeds from CTP and stock exchanges; can be wrapped as eqats market‑data plugins.
- **Gateway market‑data subscription**: the gateway automatically subscribes to contract tick data; this stream can be redirected to eqats’ signal engine via a shared message bus (e.g., ZeroMQ or Kafka).

## Signal & Execution Logic
- **Gateway HTTP API** (`/api/set_contract_target`): enables remote setting of target positions; eqats can call this endpoint to execute signals generated by its strategy modules.
- **Position alignment feature**: allows specifying target contracts with shift and close priority; eqats can use this to implement execution algorithms (TWAP, VWAP) by adjusting shift and priority.
- **Example binaries** (`crates/examples`): demonstrate query and order submission; serve as reference implementations for integrating eqats’ signal generation with the gateway.
- **CTP Futures / Tora Stock trading interfaces**: low‑level order submission, cancellation, and query functions; eqats can invoke these directly for ultra‑low‑latency execution.

## Risk Engineering
- No explicit risk‑limit or monitoring components are present in the repository. Risk controls (position limits, VaR, drawdown checks) would need to be added in eqats’ risk layer, consuming position updates from the gateway or directly from the trading APIs.

## Integration Steps
1. **Wrap market‑data sources**: create eqats adapters that call `ctp_futures` and `tora_stock` for real‑time ticks, and run the spider on a schedule to push alternative data into eqats’ ingestion pipeline.
2. **Expose gateway via eqats executor**: develop a thin Rust service (or use the existing gateway) that translates eqats order objects into HTTP POSTs to `/api/set_contract_target` or directly uses the CTP/Tora APIs for order submission.
3. **Leverage position alignment**: use the gateway’s target‑position endpoint to implement eqats’ execution algorithms; encode shift, close_priority, and target size in the request payload.
4. **Utilize utilities**: reuse `rust_share_util` for logging, configuration parsing, and helper functions across eqats modules.
5. **Deploy**: build with `cargo build` (requires clang 15.0.7) on Ubuntu 20.04/Windows 11; containerize the gateway and adapters for orchestration with eqats’ existing services.
6. **Monitoring**: feed position and order status updates from the gateway back to eqats’ risk engine for real‑time monitoring; implement custom risk checks as needed.

## Expected Benefits
- Access to CTP and Chinese stock markets via mature Rust bindings.
- Low‑latency execution through direct API calls or the gateway’s HTTP interface.
- Extensible data ingestion via the spider for alternative datasets.
- Reusable utilities reducing boilerplate across eqats components.
