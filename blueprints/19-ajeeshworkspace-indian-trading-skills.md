# Integration Blueprint: indian-trading-skills → eqats

## Overview
The `indian-trading-skills` repository provides a suite of Claude Skills focused on Indian equity markets. Its core value for eqats lies in:
- **Robust, free‑source market data pipelines** (yfinance, niftystocks, Groww/Zerodha MCP).
- **Ready‑made signal generators** (VCP screener, technical chart analysis, fundamental scoring, options strategy builder, flow tracker, scenario analyzer).
- **Embedded risk‑aware outputs** (margin requirements, risk matrices, stop‑loss guidance, scenario probabilities).

By wrapping these skills as modular components within eqats, we can rapidly extend eqats’ coverage to Indian NSE/BSE instruments while reusing existing execution and risk infrastructure.

## Data Engine Integration
| Feature | Source | How to plug into eqats |
|---|---|---|
| End‑of‑day price & volume | `yfinance`, `niftystocks` | Replace or augment eqats’ existing OHLCV ingesters with these free‑source adapters; cache results in eqats’ time‑series store (e.g., TimescaleDB). |
| Live quotes, Greeks, OI, margins | `Groww MCP`, `Zerodha Kite MCP` | Implement a thin MCP client layer that feeds real‑time tick data into eqats’ market‑data bus (e.g., Kafka topic `indian.live.ticks`). |
| News headlines | `feedparser` (RSS from Moneycontrol, Economic Times, etc.) | Connect to eqats’ news ingestion pipeline; tag articles with symbols and push to NLP sentiment module. |
| Institutional flows (FII/DII) | Web scrape of NSDL/NSE + MCP | Create a scheduled job that pulls daily flow aggregates, stores them in eqats’ `institutional_flows` table, and emits a signal when flow regime changes. |
| Reference scenario data | Built‑in CSV/JSON files (2008‑2024 patterns, sector sensitivity) | Load into eqats’ reference data service; expose via API for the Scenario Analyzer skill. |

## Signal & Execution Logic Integration
| Skill | Core Output | Integration Point in eqats |
|---|---|---|
| **Technical Analyst** | Trend, S/R, MA, volume, probabilistic scenarios (2‑4) | Feed chart images (generated by eqats’ plotting service) → skill → receive scenario weights → adjust eqats’ signal scorer (e.g., Bayesian update). |
| **NSE VCP Screener** | Ranked list with composite score, pivot levels, risk metrics | Run as a scheduled batch (daily/weekly) → output candidate list → feed into eqats’ pre‑trade signal generator; use pivot levels for stop‑loss/target calculation. |
| **India Stock Analysis** | Investment report, scorecard, bull/bear cases, risk matrix | On‑demand or periodic fundamental refresh → store scores in eqats’ `fundamental_scores` table → combine with technical scores for composite alpha model. |
| **Options Strategy Advisor** | Strategy details, Greeks, margin, ASCII P/L | When eqats detects a volatility signal (e.g., IV rank > 70), invoke the advisor to suggest straddles/iron condors; return margin requirement to eqats’ risk engine for position sizing. |
| **FII/DII Flow Tracker** | Flow regime assessment, Nifty correlation, sector rotation signals | Emit a signal when flow regime shifts (e.g., FII selling + DII absorption) → eqats’ regime‑aware overlay adjusts exposure limits per sector. |
| **Scenario Analyzer** | Base/bull/bear probabilities, sector impact, portfolio actions | Macro‑event trigger (RBI policy, budget, etc.) → skill returns scenario weights → eqats’ portfolio optimizer runs stress tests under each scenario to adjust target weights. |

## Risk Engineering Integration
| Feature | Risk Contribution | eqats Mapping |
|---|---|---|
| VCP screener risk metrics (pivot proximity, suggested stop‑loss) | Trade‑level stop & target | Use as default stop‑loss/target when generating orders from VCP signals; override with eqats’ volatility‑based stops if tighter. |
| Options Strategy Advisor margin calculation | Capital‑requirement check | Feed margin into eqats’ pre‑trade margin validator; reject orders exceeding available margin. |
| India Stock Analysis risk matrix (sector‑specific risks, promoter pledges) | Fundamental risk score | Incorporate into eqats’ fundamental risk pillar; adjust position size inversely to risk score. |
| FII/DII Flow Tracker decision matrix (regime‑based exposure limits) | Regime‑based limits | When flow regime = "FII outflow", eqats reduces max equity exposure by X% (configurable). |
| Scenario Analyzer probabilistic outcomes (base/bull/bear) & sector sensitivity | Portfolio‑level stress test | Run eqats’ optimizer under each scenario; compute VaR/CVaR; enforce scenario‑based drawdown limits. |
| Overall: probabilistic scenario probabilities | Model uncertainty | Feed scenario probabilities into eqats’ model confidence score; down‑weight signals when confidence low. |

## Example Workflow
1. **Data Pull** – Nightly job fetches EOD prices for Nifty 500 via `yfinance`; live ticks during market hours via Groww MCP.
2. **Signal Generation** – VCP screener runs, outputs top 20 breakout candidates with scores and pivot levels.
3. **Fundamental Overlay** – India Stock Analysis scores each candidate; combined alpha = 0.6*technical + 0.4*fundamental.
4. **Risk Filter** – Options Strategy Advisor computes margin for suggested protective put; flow tracker checks for adverse FII/DII regime.
5. **Scenario Adjustment** – If a macro event (e.g., RBI policy) is active, Scenario Analyzer returns bull/bear weights; final scores are tilted accordingly.
6. **Order Construction** – For each cleared signal, eqats calculates position size using volatility‑scaled Kelly, applies stop from VCP pivot, checks margin, and submits via eqats’ execution adapter.
7. **Monitoring** – Live ticker feed updates Greeks and P/L; flow tracker emits alerts if regime shifts; scenario probabilities are refreshed on news arrival.

## Implementation Steps
1. **Create adapters** for yfinance/niftystocks, Groww/Zerodha MCP, and feedparser within eqats’ `data_ingest` module.
2. **Wrap each skill** as a Python function/class returning a standardized signal dict (e.g., `{symbol, score, metadata}`) and place in `eqats/skills/indian`.
3. **Update signal combiner** to ingest outputs from the new skill modules.
4. **Extend risk engine** with margin, stop‑loss, and regime‑limit modules derived from the skills.
5. **Add scheduled jobs** (Airflow/cron) for batch skills (VCP screener, fundamental analysis) and subscribe to live tick topics for real‑time skills.
6. **Configure** eqats’ YAML to enable/disable Indian‑market features and set parameters (e.g., VCP min contractions, margin multipliers).
7. **Test** with paper‑trading account using Zerodha Kite MCP or simulated data before going live.

## Conclusion
Integrating `indian-trading-skills` equips eqats with a production‑ready, India‑specific analytics stack—data pipelines, signal generators, and risk controls—without building them from scratch. The modular design of the skills aligns well with eqats’ existing plugin architecture, allowing rapid deployment and iterative enhancement.
