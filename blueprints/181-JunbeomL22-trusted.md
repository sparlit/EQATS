# Integration Blueprint for trusted Repository into eqats

## Overview
The `trusted` repository provides a Rust‑based quantitative finance library (`quantlib`) and a developing trading engine (`trading-engine`). These components can be leveraged to enhance eqats in three domains: Data Engines, Signal & Execution Logic, and Risk Engineering.

## Data Engines
- **Data Module (`quantlib/src/data`)**: Raw market observations stored as `Arc` for thread‑safe sharing. Can replace or supplement eqats’ market‑data ingestion layer, providing a unified struct for ticks, quotes, and bar data.
- **Parameters Module (`quantlib/src/parameters`)**: Derives calculation‑ready objects (e.g., `ZeroCurve`, `DiscreteRatioDividend`) from raw data. Integrate as a preprocessing step that converts eqats’ stored market data into the parameter objects required by pricing and risk functions.
- **Time Module (`quantlib/src/time`)**: Calendar handling, holiday adjustments, and day‑count conventions. Use to standardize date handling across eqats’ data pipelines and risk calculations.

## Signal & Execution Logic
- **Trading‑Engine Crate (`trading-engine`)**: Under development library for simulating trading activities and order management. Its core abstractions (order objects, execution simulators, position keepers) can be wrapped as eqats strategy modules, enabling back‑testing and paper‑trading of signals generated by eqats’ ML models.
- **Integration Point**: Expose a Rust FFI or async RPC layer so eqats’ Python‑based signal generator can call into the trading‑engine to submit simulated orders, receive fills, and update portfolio state.

## Risk Engineering
- **Pricing Engines (`quantlib/src/pricing_engines`)**: The `Engine` takes `Arc` data and `CalculationConfiguration` to produce `CalculationResult` containing price, greeks (delta, gamma, theta, rho), and cashflows. Plug this into eqats’ risk‑monitoring service to compute real‑time greeks for positions.
- **EngineGenerator**: Groups instruments by `InstrumentCategory` and creates parallel `Engine` instances, improving Monte‑Carlo‑style risk aggregation. Use to shard risk calculations across eqats’ compute cluster.
- **Risk Limits & Monitoring**: By accessing the `CalculationResult.greeks` fields, eqats can enforce delta‑neutral, gamma‑bound, or theta‑decay limits and trigger alerts when thresholds are breached.
- **Configuration**: The `CalculationConfiguration` struct allows tuning of bump ratios, gap days for theta, etc., providing a configurable risk‑calculation knob accessible via eqats’ config service.

## Implementation Steps
1. Add `quantlib` as a dependency in eqats’ Rust core (or expose via FFI).
2. Wrap `quantlib::data::MarketData` and `quantlib::parameters::*` in eqats’ data‑ingestion pipeline.
3. Replace eqats’ date‑utility functions with those from `quantlib::time`.
4. Integrate `trading-engine` order simulation as the execution backend for eqats’ signal‑to‑order transformer.
5. Invoke `quantlib::pricing_engines::Engine::new` with market data and configuration to produce risk metrics; feed results into eqats’ risk‑limit checker and dashboard.
6. Leverage `EngineGenerator` to parallelize risk calculations across instrument categories (e.g., FX, rates, equity).

## Expected Benefits
- Unified, thread‑safe market‑data representation.
- Consistent pricing and greeks calculation aligned with industry‑standard quantlib.
- Ready‑to‑use trading‑engine simulation for strategy validation.
- Improved performance via instrument‑grouped engine instantiation.
- Configurable risk‑calculation parameters for rapid model tuning.
