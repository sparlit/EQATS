# Integration Blueprint for NseStockAnalyser Features into eqats

## Overview
The NseStockAnalyser repository provides a Python-based toolkit for fetching and analysing NSE derivative and equity data using nsetools, NSEpy, and requests. Its core capabilities—option chain analytics, put/call ratio, open-interest visualisation, and equity screening—map naturally onto the three eqats domains.

## Data Engines
- **Option Chain Analysis**: Retrieves live option chain JSON from NSE, computes max call, max put, and max pain points. In eqats this can be wrapped as a market-data feed that normalises the raw NSE payload into a canonical OptionChain schema (timestamp, underlying, strikes, call OI, put OI, IV, etc.) and stores it in the eqats timeseries store (e.g., PostgreSQL/TimescaleDB) for downstream consumption.
- **Open Interest Graphs**: Generates strike-wise OI plots (matplotlib/seaborn). The plotting logic can be refactored into eqats's visualization service, exposing OI series via an API endpoint (/market-data/oi/{symbol}) that returns JSON-encoded chart data or PNG images for dashboards.

## Signal & Execution Logic
- **Put/Call Ratio**: Calculates Put OI / Call OI (or volume-based) for each expiry. This ratio can be treated as a sentiment signal. In eqats we would create a PutCallRatio signal node that subscribes to the option-chain feed, computes the ratio, and publishes it to the signal bus. Strategies can then ingest this signal (e.g., high PCR > 1.3 → bearish bias).
- **Best Buy Stocks Screening**: Scans NSE indices (Nifty 50, Bank Nifty, etc.) and ranks equities by user-defined fundamentals/technicals. This can be turned into an eqats EquityScreen module that pulls index constituents via nsetools, applies a configurable scoring model (e.g., RSI < 30, PE < industry median), and outputs a watchlist that feeds the order-generation engine.

## Risk Engineering
- No explicit risk-management features are present in the current repository. Integration would therefore rely on eqats's existing risk limits, position-sizing, and monitoring components. Future extensions could add margin-based risk metrics derived from the option-chain data (e.g., max pain exposure) but are out of scope for this blueprint.

## Implementation Steps
1. Create a new eqats package eqats.contrib.nse_stock_analyser.
2. Wrap data-fetching functions (get_option_chain, get_put_call_ratio, get_index_constituents) behind async adapters that respect eqats's rate-limiting and retry policies.
3. Define canonical schemas in eqats.core.schemas for OptionChain, PutCallRatio, and EquityScreenResult.
4. Persist raw and derived data using eqats's TimescaleDB writer; expose read-only views via the eqats data-service API.
5. Implement signal nodes that subscribe to the relevant topics, compute the PCR and screening scores, and publish to signals.put_call_ratio and signals.equity_screen.
6. Add visualization endpoints in the eqats web-app that serve OI charts generated by the reused matplotlib code.
7. Write unit tests using mock NSE responses; add integration tests against a staging NSE endpoint (respecting usage policies).
8. Document the new module in eqats's docs, including configuration examples for enabling the NSE data feed.

## Expected Benefits
- Immediate access to reliable NSE option-chain analytics without building a custom scraper.
- Enables sentiment-driven strategies (PCR) and systematic equity screening within the eqats framework.
- Leverages existing eqats infrastructure (storage, execution, risk) while keeping the NSE-specific code isolated and maintainable.
