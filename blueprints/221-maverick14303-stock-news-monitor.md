## Integrating stock‑news‑monitor into eqats\n\n### Overview\nThe repository provides a complete news‑sentiment pipeline that scores each (headline, company) pair, validates its predictive power against next‑day NIFTY‑adjusted returns, and drives a session‑gated paper‑trading bot. Its core concepts—pair‑level scoring, self‑grading scoreboard, and risk‑aware execution—map directly onto the three eqats domains.\n\n### Data Engines\n- **Ingestion**: Adopt `monitor.py`’s feed‑scraping logic (config‑driven RSS/JSON feeds) to pull Indian financial news into eqats’ raw‑news lake.\n- **Deduplication & Ticker Matching**: Re‑use the headline‑vs‑body flag and NSE ticker map from `newslib.py` to create the canonical (headline, company) fact table.\n- **Storage**: Mirror the SQLite schema in `db.py` (or migrate to eqats’ preferred warehouse) to store raw sentiment, LLM impact/novelty, and timestamps.\n- **Self‑Healing**: Incorporate `migrate.py` as a periodic job that re‑processes the raw archive whenever ticker lists or noise regexes change, ensuring the dataset stays consistent.\n- **Universe Maintenance**: Use `build_tickers.py` to auto‑generate eqats’ tradable‑universe CSV from the bot’s current holdings or a master list.\n\n### Signal & Execution Logic\n- **Sentiment Blend**: Combine VADER baseline (`newslib.py`) with Gemini‑derived impact (`llm_sent`) and novelty (`llm_novel`) to produce a richer signal vector.\n- **Signal Aggregation**: Implement the autotrader’s formula – sentiment × learned source trust × learned sector weight – as a feature in eqats’ signal generation module.\n- **Scoreboard Feedback**: Plug `scoreboard.py`’s grading engine into eqats’ model‑validation pipeline to compute excess‑return vs NIFTY metrics, stratified by after‑hours/in‑session, novelty, and placement (headline/body). The resulting `labels` dataset can feed supervised learning.\n- **Signal Export**: Adopt `export_signal.py` to write a JSON feed (`news_signal.json`) that eqats’ execution layer can subscribe to.\n- **Execution Wrapper**: Wrap eqats’ order manager with the autotrader’s session gating: pre‑open (08:15) only queues intent; live NSE window (09:30‑14:30) performs actual fills; outside this window the system remains in data‑collection mode.\n- **Exit Rules**: Encode the –7 % stop‑loss, +15 % profit target, 15‑day max hold, and negative‑news liquidation as risk parameters in eqats’ position‑management service.\n\n### Risk Engineering\n- **Benchmarking**: Replicate the NIFTY 50 shadow portfolio by tracking a virtual Rs 5 000 index investment alongside the live paper account; report relative performance in eqats’ performance dashboard.\n- **Fee Modeling**: Apply the ~0.25 % per‑side slippage/fee assumption to all trade fills in eqats’ cost‑basis calculations.\n- **Session‑Gate Enforcement**: Use the same time‑window logic (IST) to restrict order submission to the NSE session, eliminating look‑ahead bias.\n- **Risk Limits**: Integrate the hard stop‑loss, profit target, max‑holding‑period, and news‑driven exit rules as configurable risk‑limits in eqats’ risk engine.\n- **Alerting**: Port `alerts.py`’s GitHub‑issue generation (or eqats’ internal alerting) to fire when sentiment thresholds are breached on held or watched stocks, or when a macro‑shock headline appears.\n\n### Implementation Steps\n1. Fork the repo and extract `monitor.py`, `newslib.py`, `db.py`, `migrate.py`, `llm_analyst.py`, `scoreboard.py`, `export_signal.py`, `autotrader.py`, `alerts.py`, and `config.json`.\n2. Map the SQLite schema to eqats’ storage layer (PostgreSQL / ClickHouse) preserving fields: `headline`, `company`, `ticker`, `location` (headline/body), `vader`, `llm_sent`, `llm_novel`, `timestamp`.\n3. Schedule the ingestion pipeline to run at 08:15 IST and then hourly 09:30‑14:30, 15:45, 20:00, 02:30 IST using eqats’ orchestration (e.g., Airflow or Prefect).\n4. After each ingestion run, invoke the migration step if `tickers.csv` or noise patterns changed.\n5. Run the LLM analyst on new rows to fill `llm_sent` and `llm_novel`.\n6. Update the scoreboard nightly (or after each session) to generate performance metrics and the `labels` table for model training.\n7. Export `news_signal.json` and feed it to eqats’ signal‑combiner, which multiplies by source‑trust and sector‑weight learned via online regression.\n8. Connect the signal output to eqats’ execution engine, enforcing the pre‑open queue / live‑session fill logic and the exit rules.\n9. Activate the NIFTY shadow tracker and fee model in the performance reporting module.\n10. Wire the alerting module to eqats’ notification system (Slack, email, or GitHub issues) using the same thresholds.\n\nBy following this blueprint, eqats gains a rigorously graded news‑sentiment engine, a session‑safe execution wrapper, and a transparent risk‑controlled framework that measures true incremental value over the market benchmark.
