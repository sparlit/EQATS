# Integration Blueprint for Screeni-py into eqats

## Overview
Screeni-py is a Python-based NSE stock screener that identifies breakout candidates, consolidating stocks, and user-defined chart patterns. It offers a GUI, CLI (deprecated), Docker packaging, and highly customizable screening parameters.

## Data Engine Integration
- **Market Data Ingestion**: Replace Screeni-py’s NSE data fetch with eqats’ unified market data adapter (e.g., using `eqats.data.nse` connector) to pull real‑time tick and OHLCV series.
- **Storage Layer**: Leverage eqats’ feature store (e.g., PostgreSQL + TimescaleDB or Redis cache) to cache historical NSE data, enabling low‑latency screening across universes.
- **Custom Feeds**: Expose Screeni-py’s ability to load user‑provided CSV/JSON as an eqats data source plugin, allowing alternative data (fundamentals, sentiment) to be screened alongside price data.

## Signal & Execution Logic Integration
- **Screening Core**: Encapsulate Screeni-py’s breakout probability algorithm, consolidation detector, and pattern‑matching modules as eqats signal plugins (`eqats.signals.screeni_breakout`, `eqats.signals.screeni_consolidation`, `eqats.signals.screeni_pattern`).
- **Parameterization**: Map Screeni-py’s GUI/CLI settings (price change thresholds, volume spikes, pattern eqats) to eqats strategy parameters stored in the strategy registry, enabling dynamic re‑tuning via the eqats UI or API.
- **Signal Output**: Convert the screener’s watchlist output into eqats signal events (e.g., `SignalEvent(symbol, timestamp, signal_type, strength, metadata)`) that can be consumed by the execution engine or risk modules.
- **Execution Hook**: Although Screeni-py does not place orders, its signals can be routed to eqats’ execution adapters (e.g., broker APIs) for automated entry/exit based on breakout triggers.

## Risk Engineering Integration
- **Current Gap**: Screeni-py lacks intrinsic risk controls (position sizing, stop‑loss, exposure limits). In an eqats deployment, risk management would be handled downstream:
  - Apply eqats’ risk engine to size positions according to volatility‑adjusted models.
  - Enforce max‑drawdown, sector‑exposure, and leverage limits on the signals generated by Screeni‑py.
  - Use eqats’ monitoring dashboard to track signal‑to‑fill latency and false‑positive rates of the breakout detector.

## Deployment & Operations
- **Docker**: Reuse Screeni-py’s Dockerfile as a base image for eqats’ microservice, adding eqats dependencies and exposing a REST/gRPC endpoint for signal retrieval.
- **CI/CD**: Integrate Screeni-py’s GitHub Actions workflows into eqats’ pipeline to run unit tests on the signal plugins and validate Docker builds.
- **Observability**: Export Screeni-py’s logs (via its existing logging) to eqats’ centralized logging (ELK) and expose Prometheus metrics (signals generated per second, cache hit ratio).

## Benefits
- Rapidly augment eqats’ signal library with a proven NSE‑focused breakout screener.
- Leverage Screeni-py’s GUI for analyst‑driven strategy discovery, then productionize the same logic via eqats’ automated trading stack.
- Maintain flexibility to swap data sources or extend pattern detection without altering core eqats infrastructure.

## Risks & Mitigations
- **Data Latency**: Screeni-py’s reliance on periodic NSE polls may introduce lag; mitigate by integrating with eqats’ low‑latency market data feed.
- **Model Overfitting**: Customizable parameters could lead to over‑fitted screens; enforce parameter validation and walk‑forward testing within eqats’ research framework.
- **Operational Overhead**: Running a separate screener service adds complexity; mitigate by containerizing and using eqats’ service mesh for scaling and health checks.
