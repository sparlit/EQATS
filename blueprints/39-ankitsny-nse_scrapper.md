# Integration Blueprint for nse_scrapper into eqats\n\n## Overview\nThe nse_scrapper repository provides a Go-based HTTP service that scrapes the National Stock Exchange (NSE) website for corporate information such as board meeting dates, purposes, corporate actions, and announcements. It exposes two simple REST endpoints:\n- /company?query=<symbol> for searching companies\n- /company/details?symbol=<symbol> for detailed corporate event data\n\nThese endpoints return JSON that can be consumed directly by eqats to enrich its market data feed with event‑driven fundamentals.\n\n## Integration Steps\n\n1. **Deploy the scraper as a microservice**\n   - Build the Docker image (docker build -t nse_scrapper .) or run the Go binary.\n   - Expose it on a network accessible to eqats (e.g., http://nse-scrapper:3333).\n\n2. **Create an eqats data‑ingestion adapter**\n   - Write a thin adapter in Go or Python that polls the /company/details?symbol= endpoint for a list of tradable symbols (e.g., NIFTY 50 constituents) on a configurable interval (e.g., every 30 minutes).\n   - Parse the JSON response and map fields to eqats’ canonical event schema:\n     - event_date → date\n     - event_type → purpose (e.g., Results/Dividend, Buyback)\n     - details → optional free‑text field\n   - Store the events in eqats’ time‑series database (e.g., InfluxDB) under a namespace like nse.corporate_events.\n\n3. **Signal generation**\n   - Use the corporate events as inputs to eqats’ signal engine.\n   - Example signals:\n     - Dividend‑capture: generate a long signal on the ex‑dividend date when purpose contains \"Dividend\".\n     - Buyback‑signal: generate a short‑term bullish signal when purpose contains \"Buyback\".\n     - Board‑meeting‑alert: flag heightened volatility windows around board meeting dates.\n   - Implement these as eqats strategy modules that subscribe to the nse.corporate_events stream.\n\n4. **Risk engineering considerations**\n   - Adjust position sizing or risk limits around known corporate events:\n     - Increase volatility‑based VaR buffers on board meeting days.\n     - Apply dividend‑adjustment factors to futures/options pricing models.\n   - The risk module can read the same event stream to dynamically update risk parameters.\n\n5. **Monitoring and alerting**\n   - Expose scraper health via its HTTP endpoint (/) and integrate with eqats’ observability stack (Prometheus + Grafana).\n   - Set up alerts for scraping failures or latency spikes.\n\n## Example eqats configuration snippet\n\n```yaml\ndata_engines:\n  - name: nse_scrapper\n    type: http\n    url: http://nse-scrapper:3333\n    refresh_interval: \"30m\"\n    symbols: [\"INFY\", \"TCS\", \"RELIANCE\"]\n\nsignal_execution:\n  - name: dividend_capture\n    subscribe: [\"nse.corporate_events\"]\n    condition: \"event.purpose contains 'Dividend'\"\n    action: \"generate_long_signal\"\n\nrisk_engineering:\n  - name: event_volatility_adjust\n    subscribe: [\"nse.corporate_events\"]\n    rule: \"if event.purpose in ('Board Meeting', 'Results/Dividend') then increase_var_buffer by 0.2\"\n```\n\n## Benefits\n- Provides timely, structured corporate‑event data without relying on external vendors.\n- Enables event‑driven strategies that can improve alpha capture around dividends, buybacks, and board decisions.\n- Integrates cleanly with eqats’ existing data‑engine, signal, and risk layers via simple HTTP polling and event streaming.\n\n## Caveats\n- The scraper depends on the structure of the NSE website; changes to the site may break parsing.\n- Rate‑limiting should be respected to avoid being blocked by NSE.\n- Data latency is tied to the polling frequency; for near‑real‑time needs consider pushing updates via websockets (future extension).\n
