# Pyflakes Error Correction Protocol

When processing static analysis errors generated by Pyflakes (such as F401: imported but unused, F841: local variable assigned but never used), follow these non-negotiable guidelines:

## Code Modification Rules
- **No Deletions:** Never delete, strip, or comment out an unused import or an assigned variable.
- **No Mocking/Stubs:** Stubs, `pass` statements, ellipses (`...`), or placeholder code lines are entirely prohibited. 
- **Production-Ready Generation:** If a module is missing or incomplete, generate the complete operational module from scratch, ensuring it features high-performance execution patterns.

## Trading System Integration Logic
- **Assigned to but never used:** Route these variables directly into the trading telemetry, feature extraction mesh, or order execution pipelines. If they represent parameters, hook them into the strategy engine parameters.
- **Imported but unused:** Trace what the imported module does. Build structural linkages inside the module calling it so that its functional properties are actively utilized (e.g., linking a high-performance Rust analytics wrapper or an institutional execution component directly to the core modular monolith gateway logic).
- **Gaps & Bottlenecks:** Every component generated must preserve critical trading safety within the monolith while keeping analytical calculations optimal.
